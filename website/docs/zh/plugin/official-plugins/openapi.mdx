# @rspress/plugin-openapi <SourceCode href="https://github.com/web-infra-dev/rspress/tree/main/packages/plugin-openapi" />

import { SourceCode, PackageManagerTabs } from '@rspress/core/theme';

将 OpenAPI 描述文件转换为 Rspress 接口文档。每个接口都有独立页面，读者可以查看参数、请求体和响应结构，复制不同语言的请求示例，也可以填写参数后点击 **Send** 直接调用接口。

文档复用 Rspress 的侧边栏、Tabs 和代码块，支持暗色模式和移动端。适用于为 HTTP API 编写参考文档；如果需要为 TypeScript 模块生成文档，请使用 [plugin-typedoc](./typedoc)。

## 安装

需要 Node.js 22.12.0 或更高版本。

<PackageManagerTabs command="add @rspress/plugin-openapi -D" />

## 生成第一份接口文档

### 准备 OpenAPI 文件

在项目根目录创建 `openapi.yaml`。下面的示例定义了一个获取行星列表的接口：

```yaml title="openapi.yaml"
openapi: 3.1.0
info:
  title: Planets API
  version: 1.0.0
servers:
  - url: https://api.example.com
paths:
  /planets:
    get:
      operationId: getAllPlanets
      summary: 获取行星列表
      description: 返回行星列表，可通过 limit 控制返回数量。
      tags:
        - Planets
      parameters:
        - name: limit
          in: query
          description: 返回的最大数量。
          schema:
            type: integer
            default: 10
      responses:
        '200':
          description: 请求成功
          content:
            application/json:
              schema:
                type: array
                items:
                  type: object
                  properties:
                    name:
                      type: string
              example:
                - name: Mars
                - name: Earth
```

`https://api.example.com` 是占位地址。要尝试 Send，请将 `servers[].url` 替换为你的 API 地址。

### 注册插件

在 `rspress.config.ts` 中注册插件，并添加一个指向接口页面的导航入口：

```ts title="rspress.config.ts"
import { defineConfig } from '@rspress/core';
import { pluginOpenAPI } from '@rspress/plugin-openapi';

export default defineConfig({
  root: 'docs',
  plugins: [
    pluginOpenAPI({
      input: './openapi.yaml',
      routePrefix: '/api',
    }),
  ],
  themeConfig: {
    nav: [{ text: 'API', link: '/api/getallplanets' }],
  },
});
```

启动 Rspress 后，打开 `/api/getallplanets`。侧边栏会显示 **Planets** 分区标题，以及带有绿色 **GET** 标签的“获取行星列表”链接。

插件会在启动和构建时生成页面，无需手动创建 MDX 文件或 `_meta.json`。生成内容不会写入你的 `docs` 源目录。修改 OpenAPI 文件或它引用的文件后，需要重启开发服务。

## 页面和侧边栏如何组织

| OpenAPI 字段           | 文档中的用途                                                 |
| ---------------------- | ------------------------------------------------------------ |
| `operationId`          | 生成页面路径，例如 `getAllPlanets` 对应 `/api/getallplanets` |
| `summary`              | 页面标题和侧边栏链接文字；未设置时使用操作 ID                |
| `description`          | 接口或字段的说明文字                                         |
| `tags[0]`              | 侧边栏分区标题；未设置时使用 `info.title`                    |
| HTTP 方法              | 接口和侧边栏的彩色标签，例如 GET 为绿色、POST 为蓝色         |
| `example` / `examples` | 请求或响应的示例内容                                         |

每个接口生成一个页面。没有 `operationId` 时，插件使用 HTTP 方法和路径生成标识，例如 `GET /planets` 对应 `/api/get-planets`。标识会转成小写，并将不适合 URL 的字符替换为连字符；重复标识或转换后冲突的路径会使构建失败。

`routePrefix` 只设置页面路径前缀，不会额外生成 `/api` 总览页。导航链接应指向具体接口页面。已有站点配置了 `base` 时，无需将它重复写入 `routePrefix`。

如果想自己安排侧边栏顺序，关闭自动侧边栏并配置 `themeConfig.sidebar`：

```ts
pluginOpenAPI({
  input: './openapi.yaml',
  sidebar: false,
});
```

```ts
// rspress.config.ts 中的 themeConfig
sidebar: {
  '/api/': [
    { sectionHeaderText: 'Planets' },
    { text: '获取行星列表', link: '/api/getallplanets', tag: 'GET' },
  ],
},
```

自动生成侧边栏时，插件会替换 `routePrefix` 对应的侧边栏配置，保留其他路径的侧边栏。

## 使用远程描述文件

`input` 也可以是 HTTP(S) URL：

```ts
pluginOpenAPI({
  input: 'https://api.example.com/openapi.yaml',
  routePrefix: '/api',
});
```

Rspress 启动或构建时需要能够访问该 URL，以及通过 `$ref` 引用的外部文件。远程描述文件中相对的 Server URL 会相对于描述文件的 URL 解析。

读取本地服务或内网提供的描述文件时，设置 `allowPrivateUrls: true`：

```ts
pluginOpenAPI({
  input: 'http://localhost:3000/openapi.json',
  allowPrivateUrls: true,
});
```

此选项控制描述文件的加载，不会为 Send 请求配置代理或绕过 CORS。`input` 还接受 OpenAPI 3 文档对象，适合在配置中导入已有 JSON 数据。

## 在文档中调试接口

1. 在 **Server URL** 中确认或修改 API 地址。
2. 展开 **Parameters**，填写路径、查询或请求头参数。数组和对象参数使用 JSON，例如 `["red", "blue"]`。
3. 接口需要鉴权时，展开 **Authorization** 并填写凭证。
4. 如有请求体，展开 **Request body**，选择内容类型并编辑内容。
5. 点击 **Send**，查看实际响应的状态码、耗时、响应体和浏览器可读取的响应头。

请求期间可以点击 **Cancel** 取消，超过 30 秒会超时。右侧的 **Response example** 来自描述文件，实际请求结果会单独显示。

请求示例支持 cURL、JavaScript、Go、Python、Java、C# 和 Rust。切换 Tabs 可以查看对应代码，并使用代码块的复制按钮。参数、凭证和请求体填写完整后，示例会随输入更新。

### 鉴权方式

| 方式                   | 如何填写                                               |
| ---------------------- | ------------------------------------------------------ |
| API Key                | 填写 key，支持放在请求头或查询参数中                   |
| Bearer                 | 填写 token，不需要加 `Bearer ` 前缀                    |
| Basic                  | 填写 `username:password`                               |
| OAuth / OpenID Connect | 粘贴已有的 access token；不提供登录或获取 token 的流程 |

凭证仅保存在当前页面内存中，不会持久化。如果接口声明了多种可选鉴权方案，可以选择其中一种；同一方案中的多个凭证需要一起填写。

### 只展示文档

不需要在线调试时，可以关闭编辑区域和 Send 按钮，保留接口说明与代码示例：

```ts
pluginOpenAPI({
  input: './openapi.yaml',
  playground: false,
});
```

## 配置项

| 选项               | 类型                        | 默认值   | 说明                                                                                           |
| ------------------ | --------------------------- | -------- | ---------------------------------------------------------------------------------------------- |
| `input`            | `string \| OpenAPIDocument` | 必填     | JSON/YAML 文件路径、HTTP(S) URL 或 OpenAPI 3 文档对象；相对文件路径基于运行 Rspress 的工作目录 |
| `routePrefix`      | `string`                    | `'/api'` | 生成页面的 URL 前缀                                                                            |
| `sidebar`          | `boolean`                   | `true`   | 自动生成侧边栏分区和接口链接                                                                   |
| `playground`       | `boolean`                   | `true`   | 显示请求编辑区域和 Send 按钮                                                                   |
| `allowPrivateUrls` | `boolean`                   | `false`  | 允许从 localhost 或内网 URL 加载描述文件                                                       |

## 常见问题和当前限制

### Send 提示网络错误

Send 从读者的浏览器直接发送请求。检查 Server URL 和网络连接，并确保 API 服务允许文档站点来源的 CORS 请求。插件不提供代理，也不会携带浏览器 cookie；将文档部署为静态网站后，这些条件仍然适用。

### 支持哪些规范和请求格式

支持 OpenAPI 3.0、3.1 的 JSON/YAML 描述文件，以及 Swagger 2.0 文件转换。当前不支持 OpenAPI 3.2、webhooks 和 callbacks。

在线调试支持 JSON、纯文本及 URL-encoded 请求体。路径参数支持 `simple`，查询参数支持 `form`、`deepObject` 及空格或竖线分隔的数组。当前不支持文件上传、cookie 鉴权或其他参数序列化方式；遇到不支持的格式时会提示错误。

### 为什么描述中的 Markdown 没有格式化

描述当前按纯文本显示，不解析其中的 Markdown、HTML 或 MDX。

### 为什么自动生成的示例不符合业务约束

自动推导的示例仅供参考，并不保证满足全部 schema 约束。建议在描述文件中提供明确的 `example` 或 `examples`。递归结构的展示和示例生成都有深度限制。较大的描述文件也会增加生成页面的数据体积。
