# WebMCP

<VersionBadge version="2.1.0" />

Rspress can expose documentation tools to browser agents through the native [WebMCP API](https://developer.chrome.com/docs/ai/webmcp/imperative-api). It is built into core and enabled by default. Enable Markdown generation to make all six tools available:

```ts title="rspress.config.ts"
import { defineConfig } from '@rspress/core';

export default defineConfig({
  llms: true,
});
```

Set `webMcp: false` to disable the Rspress built-in tools. The [`useWebMcp`](/ui/hooks/use-web-mcp) hook remains available for registering custom tools.

WebMCP is experimental and requires a browser with `document.modelContext` enabled in a secure context, such as HTTPS or localhost. Unsupported browsers continue to render the site normally. Rspress does not install a browser polyfill or an MCP server.

See [AI config](/api/config/config-agent#webmcp) for the configuration reference.

## Built-in tools

| Tool                       | Purpose                                                                                                           |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `rspress_get_site_info`    | Site metadata, locales, versions, navigation, and the active sidebar.                                             |
| `rspress_list_pages`       | Filter and paginate page metadata, defaulting to the active language and version. Works independently of search.  |
| `rspress_get_page`         | Read metadata, frontmatter, TOC, and SSG-MD Markdown for a known route without navigating.                        |
| `rspress_get_current_page` | Read metadata, frontmatter, TOC, and SSG-MD Markdown for the current page.                                        |
| `rspress_search_docs`      | Search the local documentation index for the active language and version.                                         |
| `rspress_navigate`         | Navigate to a known internal route, then return committed page metadata, section routes, and previous/next pages. |

Paths are absolute within the documentation site, excluding the configured `base`. For a site hosted at `/docs/`, pass `/guide` to navigate to `/docs/guide.html` (or `/docs/guide` with `route.cleanUrls: true`). Navigation preserves query strings and hashes and rejects unknown or external routes. A navigation superseded by another route or interrupted by a page error rejects instead of returning stale page metadata. Cancelling a tool call stops waiting for its result; it does not undo an already started navigation.

`rspress_list_pages` accepts `query`, `lang`, `version`, `limit` (1–100, default 50), and `offset` (default 0). Its query matches page titles, descriptions, routes, and headings. `rspress_search_docs` accepts `query` and `limit` (1–20, default 10).

## Markdown and search availability

The two page-reading tools require `llms: true` in production to generate page Markdown through [SSG-MD](/guide/basic/ssg-md). Run `rspress build` followed by `rspress preview` to try all six tools. Without `llms: true`, or when using the development server, no SSG-MD output is generated, so Rspress omits `rspress_get_page` and `rspress_get_current_page`.

Page-reading tools are independent of the theme UI. With Markdown generation enabled, they remain available when `LlmsHint` is unmounted, `themeConfig.llmsUI` is disabled, or `themeConfig.llmsUI.injectLlmsHint` is set to `false`.

The search tool shares the default search panel's provider and configured `beforeSearch`, `onSearch`, and `afterSearch` hooks. The index is initialized when the panel opens or an agent first searches. Closing the popup keeps the tool available; unmounting or replacing the default search panel removes it. Custom search components can register their own tool with `useWebMcp`. Switching language or version selects the corresponding index; `search.versioned: false` searches across versions. The search tool is omitted when local search is disabled or the active group has no index. Algolia integration is not supported yet: sites using `@rspress/plugin-algolia` retain their existing DocSearch UI, but do not expose a WebMCP search tool. Page listing and reading remain available.

WebMCP uses the existing development page-data and search-index lifecycle. It does not add full-site recomputation on edits; metadata and index updates remain subject to the existing HMR behavior.

## Try a tool

In a supported browser, discover a tool and invoke it. Experimental browser implementations may expose a serialized schema and expect JSON-encoded arguments; the example handles both forms. Replace `/guide` with an existing page route:

```js
const tools = await document.modelContext.getTools();
const tool = tools.find(tool => tool.name === 'rspress_get_page');
if (!tool) throw new Error('Page-reading tool is unavailable');
const input = { routePath: '/guide' };
const args =
  typeof tool.inputSchema === 'string' ? JSON.stringify(input) : input;
const result = await document.modelContext.executeTool(tool, args);
console.log(typeof result === 'string' ? JSON.parse(result) : result);
```

## Cross-origin agents

Same-origin and browser-integrated agents need no extra configuration. To expose the built-in tools to specific secure origins:

```ts
export default defineConfig({
  llms: true,
  webMcp: {
    exposedTo: ['https://agent.example'],
  },
});
```

The browser also applies its WebMCP permissions policy and discovery rules. See the [cross-origin API documentation](https://developer.chrome.com/docs/ai/webmcp/imperative-api#cross-origin-iframes).

## Custom tools

Use [`useWebMcp`](/ui/hooks/use-web-mcp) from `@rspress/core/runtime` to register tools in your own components. The built-in tools use the same hook in `App` and the search panel. Tool availability follows the owning component; there are no separate search or Markdown switches in `webMcp`.
