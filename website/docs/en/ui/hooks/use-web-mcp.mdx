# useWebMcp

`useWebMcp` registers a tool with the browser's experimental WebMCP API and removes it when the component unmounts. Import it from `@rspress/core/runtime`:

```tsx
import { usePage, useWebMcp } from '@rspress/core/runtime';

export function PageTitleTool() {
  const { page } = usePage();

  useWebMcp({
    name: 'my_site_page_title',
    description: 'Get the current page title',
    annotations: { readOnlyHint: true },
    execute: () => ({ title: page.title }),
  });

  return null;
}
```

Mount the component where the capability belongs. Keep site-wide tools in a persistent component; mount tools specific to a page with that page. Tool names must be unique across the document, including the [built-in tools](/guide/basic/webmcp).

Custom tools do not require `webMcp: true` in the Rspress config. That option only enables the built-in documentation tools. The hook requires native `document.modelContext` support in a secure context, does not install a polyfill, and is safe to render during SSR. Initialize any externally supplied runtime before mounting tool components.

## Options

| Option                    | Description                                                                                                                                |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `name`                    | Required unique tool name.                                                                                                                 |
| `description`             | Required description for agents.                                                                                                           |
| `title`                   | Optional display title.                                                                                                                    |
| `inputSchema`             | JSON Schema describing the input. No schema library is required.                                                                           |
| `execute(input, options)` | Required function returning a JSON-serializable value or a promise. `options.signal`, when provided, carries cancellation from the caller. |
| `enabled`                 | Whether to register the tool. Defaults to `true`; setting it to `false` unregisters the tool.                                              |
| `annotations`             | Optional `readOnlyHint` and `untrustedContentHint` hints.                                                                                  |
| `exposedTo`               | Optional array of additional secure origins allowed to discover the tool.                                                                  |

Use `WebMcpOptions<TInput, TResult>` or annotate the input parameter to type your handler. The hook does not infer argument types from JSON Schema or validate arguments itself; validate untrusted input in the handler. Results pass through without MCP response wrapping, and execution errors propagate to the caller.

```tsx
useWebMcp({
  name: 'my_site_lookup',
  description: 'Look up a documentation entry',
  inputSchema: {
    type: 'object',
    properties: { query: { type: 'string' } },
    required: ['query'],
    additionalProperties: false,
  },
  async execute(input: { query: string }, { signal }) {
    if (typeof input?.query !== 'string' || !input.query.trim()) {
      throw new TypeError('query must be a non-empty string');
    }
    const response = await fetch(
      `/api/lookup?q=${encodeURIComponent(input.query)}`,
      { signal },
    );
    if (!response.ok) throw new Error(`Lookup failed: ${response.status}`);
    return response.json();
  },
});
```

## Return value and lifecycle

The hook returns `{ supported, registered, error }`, typed as `WebMcpState`. `supported` reports browser API availability; `registered` becomes `true` after registration succeeds; `error` contains a registration error, such as a duplicate name. Registration errors are also logged to the console. During SSR, the values are `false`, `false`, and `null`.

Each call uses the latest **committed** handler, including its props and state. Updating the handler does not re-register the tool. Changes to the serialized tool metadata (name, schema, description, annotations, or exposed origins) trigger cleanup and re-registration. Equivalent inline objects with the same property order keep the existing registration.

Disabling or unmounting removes the registration. An already started execution must handle cancellation and cleanup in its own handler; removing the tool does not undo its effects.
